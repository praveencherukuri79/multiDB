🚀 MultiDB + Flowable – API Test Page

Base URL: http://localhost:8080 | Start the app first: mvn spring-boot:run

💡 Recommended: Try the Orchestrator Pattern endpoints first to see multi-database coordination in action!
🎯 Orchestrator Pattern (Multi-DB Workflows)

These endpoints coordinate operations across Primary, Audit, and Reporting databases. Each call triggers 3 separate transactions.

1. Place Order (Eventual Consistency)

curl -X POST http://localhost:8080/api/orchestrator/orders \
  -H "Content-Type: application/json" \
  -d '{"customerName":"John Doe","productName":"Laptop","amount":1299.99}'

✓ Saves order to Primary DB → ✓ Logs to Audit DB → ✓ Updates metrics in Reporting DB

2. Place Order with Saga (Compensation)

curl -X POST http://localhost:8080/api/orchestrator/orders/saga \
  -H "Content-Type: application/json" \
  -d '{"customerName":"Jane Smith","productName":"Phone","amount":899.99}'

⚠️ If any step fails, previous steps are automatically compensated (rolled back)

3. Get Order Details (Multi-DB Read)

curl http://localhost:8080/api/orchestrator/orders/1/details

Fetches order from Primary DB + audit history from Audit DB in one response

4. Get Single Order

curl http://localhost:8080/api/orchestrator/orders/1

Simple read from Primary DB only

📊 Individual Service Endpoints (Direct DB Access)

These endpoints interact with a single database directly. No cross-DB coordination.

Primary DB – Create Order

curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{"orderNo":"ORD-001","customerId":1001,"totalAmount":99.50}'

Direct write to Primary DB only (no audit or reporting)

Primary DB – Get Order by OrderNo

curl http://localhost:8080/api/orders/ORD-001

Reporting DB – Upsert Daily Sales

curl -X POST http://localhost:8080/api/reporting/daily-sales \
  -H "Content-Type: application/json" \
  -d '{"date":"2025-02-05","ordersCount":42,"grossAmount":12500.00}'

Direct write to Reporting DB only

Reporting DB – Get Daily Sales

curl http://localhost:8080/api/reporting/daily-sales/2025-02-05

Audit DB – Write Event

curl -X POST http://localhost:8080/api/audit/events \
  -H "Content-Type: application/json" \
  -d '{"eventType":"ORDER_CREATED","actor":"system","subjectId":"ORD-001","payloadJson":"{}"}'

Direct write to Audit DB only

Audit DB – Get Events for Actor

curl http://localhost:8080/api/audit/events/system
🔄 Flowable Process Engine (Uses Primary DB)

Flowable shares the Primary database. All process engine tables (ACT_*) are in Primary DB.

Deploy Process Definition

curl -X POST http://localhost:8080/api/flowable/deploy

Deploys the demo BPMN process to Flowable engine

Start Process Instance

curl -X POST http://localhost:8080/api/flowable/process/start \
  -H "Content-Type: application/json" \
  -d '{"processKey":"demoProcess"}'

Starts a new process instance

List Deployments

curl http://localhost:8080/api/flowable/deployments

List Process Instances

curl http://localhost:8080/api/flowable/process/instances
📋 Endpoint Comparison
Type Endpoint Pattern Databases Touched Use Case
Orchestrator /api/orchestrator/* Primary + Audit + Reporting Business workflows
Individual /api/orders/* Primary only Direct DB operations
Individual /api/reporting/* Reporting only Analytics updates
Individual /api/audit/* Audit only Audit logging
Flowable /api/flowable/* Primary (ACT_* tables) Process automation
